## 1. Claude native schema（以真实记录为准，非猜测）

顶层记录 `type` 字段，真实观测到的取值及用途：

| `type` | 观测次数(合计) | 是否用户证据 | 用途 |
|---|---|---|---|
| `user` | ~870 | **是**（部分） | 人类 prompt 或 tool_result 投递 |
| `assistant` | ~1650 | **是** | 模型输出（text / thinking / tool_use） |
| `system` | ~57 | 否（内部） | `subtype=api_error`（429/503/断连重试）、`subtype=compact_boundary`（压缩标记） |
| `queue-operation` / `atis-latch` / `attachment` / `ai-title` / `custom-title` / `last-prompt` / `file-history-snapshot` / `file-history-delta` / `mode` | 大量 | 否 | 簿记/非对话记录，忽略 |

### `user` 记录（真实示例）
```json
{"parentUuid":"...","isSidechain":false,"promptId":"...","type":"user",
 "message":{"role":"user","content":[{"type":"text","text":"..."} |
                                      {"tool_use_id":"call_00_...","type":"tool_result","content":"...","is_error":false} |
                                      "...string..." ]},
 "uuid":"...","timestamp":"2026-09-02T13:09:00.198Z","permissionMode":"auto",
 "origin":{"kind":"human"},"promptSource":"sdk","userType":"external",
 "entrypoint":"claude-vscode","cwd":"<repo>","sessionId":"...","version":"2.1.258","gitBranch":"main"}
```
- `message.content` 可为 `string` 或 block 数组；block 类型：`text`、`tool_result`。
- **可选顶层结构化字段 `toolUseResult`**：`{type:"create"|"update"|"file_unchanged"|"text", filePath, content}`（Edit/Write 时出现）。观测分布：`text:229, ?:815, file_unchanged:6, create:36, update:1`。该字段是**旁证**，不作为成功判据。

### `tool_result` block（已统计 1087 个）
字段：`tool_use_id`(1087)、`type:"tool_result"`、`content`、`is_error`(620/1087 出现)。
- `is_error === true` 表示失败（例：`"Exit code 49\nPython was not found..."`）。
- 失败时 Claude 会置 `is_error=true`；未置 true 视为正常完成。
- **Claude 没有结构化的 `exit_code` 字段**（仅在 content 文本里出现 "Exit code N"），因此成功/失败只能以 `is_error` 为准。

### `assistant` 记录（真实示例）
```json
{"parentUuid":"...","isSidechain":false,
 "message":{"id":"msg_...","type":"message","role":"assistant","model":"claude-sonnet-4-6",
   "content":[{"type":"text","text":"..."},
              {"type":"thinking","thinking":"..."},
              {"type":"tool_use","id":"call_00_...","name":"Bash","input":{"command":"...","description":"..."}}],
   "stop_reason":"tool_use","stop_sequence":null,"usage":{...}},
 "apiBlockIndex":0,"type":"assistant","uuid":"...","timestamp":"...","effort":"medium",
 "userType":"external","entrypoint":"claude-vscode","cwd":"...","sessionId":"...","version":"2.1.258","gitBranch":"main"}
```
- content block 类型：`text`、`thinking`、`tool_use`。
- `tool_use` = `{id, name, input}`。**tool_use.id ↔ tool_result.tool_use_id** 即关联键。

### 工具 schema（真实，按 name）
| name | input 键 | 是否结构化 operation |
|---|---|---|
| `Bash` / `PowerShell` | `command`,`description` | **是**（shell） |
| `Read` | `file_path`,`limit?`,`offset?` | 否（只读） |
| `Glob` | `pattern` | 否 |
| `Grep` | `pattern`,`path?`,`output_mode?`,`-n?`,`glob?`,`head_limit?`,`ignore_case?` | 否 |
| `Edit` | `replace_all`,`file_path`,`old_string`,`new_string` | **是**（file edit） |
| `Write` | `file_path`,`content` | **是**（file write） |
| `TodoWrite`,`WebSearch`,`WebFetch`,`Skill`,`Artifact`,`AskUserQuestion`,`SendMessage`,`Monitor`,`TaskOutput`,`TaskStop` | 各异 | 否（只读/内部） |
| `Agent` | `description`,`subagent_type`,`prompt` | **否（内部，subagent 生成）** |

### subagent / sidechain
- 子代理是**独立文件** `subagents/agent-<id>.jsonl`，记录含 `agentId` 且 `isSidechain:true`。
- 主会话里 spawn 子代理 = `Agent` tool_use；结果以 `user` 消息内容 `<task-notification>...` 注入。
- 顶层 `isSidechain` 字段每个记录都有（观测全部为 `false`，subagent 文件里为 `true`）。

### compaction / summary
- 压缩标记 = `system` 记录 `subtype:"compact_boundary"`：
```json
{"type":"system","subtype":"compact_boundary","content":"Conversation compacted","level":"info",
 "compactMetadata":{"trigger":"auto","preTokens":167013,"postTokens":8551,"cumulativeDroppedTokens":158462,
   "preservedSegment":{"headUuid":"...","anchorUuid":"...","tailUuid":"..."},"preservedMessages":{...}},
 "logicalParentUuid":"...","timestamp":"...","cwd":"...","sessionId":"..."}
```
- 紧接其后的 `user` 消息 content 以
  `"This session is being continued from a previous conversation that ran out of context. The summary below covers the earlier portion..."` 开头
  —— 这是**折叠历史的唯一代表**（含 Primary Request and Intent / Success criteria 等）。

### session id / cwd
- 每个 `user`/`assistant`/`system` 记录都有 `sessionId` 与 `cwd`（真实：`<repo>`）。文件名即 session uuid（`<session>.jsonl`）。

## 2. Parser reuse 判定

- 已安装的 `@anthropic-ai/claude-code@2.1.258` 是 **native-binary wrapper**：`package.json` 的 `files` 仅含 `bin/claude.exe`、`install.cjs`、`cli-wrapper.cjs`、`sdk-tools.d.ts`，`dependencies:{}`。**没有可导入的 JS transcript parser / 导出类型 / 纯读解析 helper**。
- 结论：**无稳定、纯读、无副作用的官方 parser 可复用**。需要设计一个**窄的 Claude JSONL parser**，只识别本报告第 1 节已验证的 schema。不把 Claude transcript 伪装成 Codex rollout。
- 复用的边界：margin 仓库**已有** native Claude discovery（`src/agents/externalSessionDiscovery.js` 的 `discoverClaudeSessions`）——含 `completeRecords`（尾部部分行安全）、sidechain/subagent 排除、`textContent` 过滤、cwd/model/time/title 提取。这条 discovery 层可直接作为 capture 基础，只缺 evidence extractor。

## 3. Foreground / sidechain / compaction 规则

**关键发现：Claude 的 schema 与 Pi 的 `buildContextEntries`（SDK 分支语义）不同。**

- 本机所有主会话文件 `isSidechain:false`、物理顺序即对话顺序；`parentUuid` 在文件内**不是严格线性链**（实测 5 处断链：tool_result 的 parent 指向其 tool_use 消息、system 记录的 logicalParentUuid 等）。Claude 把 resumed/rewritten 历史以 append 形式存在同一文件。
- 因此窄 parser **不做 parentUuid 树重建**（不可靠且非 native facts 必需），采用**物理 append 顺序 + 显式 native 标记过滤**：

| 内容 | 筛选依据 | 是否进入主 evidence |
|---|---|---|
| subagent/sidechain | 记录 `isSidechain===true` 或含 `agentId`；`Agent` tool_use；`task-notification` user content | **否**（不进入 foreground Progress） |
| `system subtype=api_error` | 内部重试/错误 | 否 |
| 非对话簿记（queue/atis/attachment/ai-title/last-prompt/file-history/mode） | type 白名单 | 否 |
| `compact_boundary` + 紧接 summary user 消息 | 压缩标记 | 作为 `Internal context/control` 单点保留，**不与折叠历史重复** |
| 其余 `user`(真实 prompt) / `assistant` / `tool_use` / `tool_result` | 前台对话 | **是** |

- **分支（abandoned rewrite）**：Claude 无第一类“活跃 vs 废弃 sibling branch”概念可像 Pi SDK 那样过滤。本机样本无 rewind 场景；窄 parser 视整文件为活跃对话（discovery 已排除 subagent 文件）。这是与 Pi 的唯一结构性差异，记录为已知限制。
- compact summary 的 user 消息**不得成为 Goal 候选**（它是原目标的重述，非新请求）。

## 4. Tool/result 关联规则

关联键：`tool_use.id` ↔ `tool_result.tool_use_id`。构建索引：遍历所有 `user` 记录的 `tool_result` block，`map[tool_use_id] = {content, is_error, line, toolUseResult}`。

- **Bash/PowerShell**：`status = is_error===true ? 'failed' : 'succeeded'`；`commandKinds(command)` 判 test/git/possibleWrite；产生 `Shell command` operation（+ `Test execution` 当 test）。
- **Edit/Write**：input 提供 `file_path` + `old_string/new_string`（Edit）或 `file_path` + `content`（Write）；用 `toolUseResult.filePath` 交叉印证；产生 `File edit/write` operation 与 edits[]。status 同样以 `is_error` 为准（Edit 无 `exit_code`）。
- **Read/Grep/Glob/WebSearch/WebFetch/Skill/Artifact/AskUserQuestion/TodoWrite**：只保留 `Tool call` / `Tool result` 节点，不产生 structured operation。
- **Agent/Monitor/TaskOutput/TaskStop**（subagent/内部）：保留 Tool 节点作 provenance，不产生 operation，不入 Progress。
- **未匹配 / in-flight**：tool_use 在捕获内无对应 tool_result → `status:'unknown'`、`confidence:'Uncertain'`，**绝不标 succeeded**，并产生 warning。
- **tool error**：`is_error===true` → `status:'failed'`（已观测到 Bash "Exit code 49"、WebFetch 域名拒绝 等真实 error）。
- **truncated result**：Claude 记录**无结构化 truncation 标记**（区别于 Pi 的 `details.truncation`）。content 按原样作为已观测输出，outcome 以 `is_error` 为准。

## 5. Evidence mapping（Claude → margin.evidence.v1）

不新增第二套 schema。复用 `piEvidence.js` 的产物形状（`{schemaVersion:'margin.evidence.v1', source, nodes, operations, warnings, coverage}`）与节点种类。

| Claude native 记录 | evidence 节点 / operation | provenance | confidence / outcome |
|---|---|---|---|
| `user` content text（真实 prompt，非 tool_result/非 task-notification/非 summary） | `User requirement` | line pointer | `Confirmed`（scope：请求已提出，非已完成） |
| `assistant` content text | `Assistant claim` | line pointer | `Inferred`（未验证叙述） |
| `tool_use`（全部） | `Tool call` | line pointer | `Confirmed` |
| `tool_result` | `Tool result`（resultIds 关联） | line pointer | `Confirmed`；scope 按 `is_error` |
| Bash/PowerShell tool_use+result | `Shell command` operation（+`Test execution` 当 test） | line pointer(s) | status=`succeeded/failed/unknown` 按 `is_error`+匹配 |
| Edit/Write tool_use+result | `File edit/write` operation + edits[] | line pointer(s) | status 同上 |
| `compact_boundary` + summary user | `Internal context/control`（单点） | line pointer | `Confirmed`（折叠历史由 summary 代表一次） |
| `system api_error` | 丢弃 | — | — |

**不生成** Goal / Progress / Pending / Validation / Follow-up —— 这些继续由 Shared Core（`distiller.js` + `repo-truth.js`）负责。extractor 只提供 native facts。

## 6. Fresh capture 设计

**完全继承现有 Shared Core，无需新设计：**

- `captureSession(sessionMeta, snapshotPath, {refreshSnapshot:true})`：冻结到最后一个完整 `\n`，剔除尾部部分/畸形 JSONL，计算 `sha256`，写 snapshot + `.capture.json`。
- resumed Claude session 新 append 后再次 Copy/Save → `refreshSnapshot:true` 重新冻结，capture hash 更新 → 重新 generation 必须刷新（`createHandoffArtifact` 已保证）。
- canonical ID 与 Windows-safe 存储分离：`snapshotPathForCanonicalSession` 用 sha256 做磁盘键，canonicalId 只在 provenance。
- `sourceId / nativeSessionId / sessionId / canonicalId / cwd / agentType` 全在 capture 里。
- 复用 `httpAdapter` 的 `/api/handoff/generate` 与 `saveHandoffArtifact`（`.margin/HANDOFF.md`）管道。
- 新增 `claudeSessionSource.js`（等价 `readPiSessionSource`）读取快照为 `{records, capture, session:{cwd}}`。

## 7. Shared Core compatibility

- **`evidence.js`（Codex 专用）不与 Claude 共享** —— Claude 用自己 extractor（如 `piEvidence.js` 一样），Shared Core 的 `distiller / repo-truth / render / smartSelect / resume-summary / save` 都是 agent 无关的，消费 `{nodes, operations, warnings, source}`。
- Claude extractor 必须产出与现有一致的 operation 形状：`{id, name, command?, cwd?, status, confidence, reason, mapping, edits?, kinds?, evidence, warnings}`。`commandKinds`、`patchEdits`、`operationOutcome` 均工具无关。
- **Codex-specific assumption 检查**：
  - `distiller` 用的 `o.kinds?.test`、`o.status`、`o.command`、`o.edits`、`o.cwd` —— Claude extractor 全部提供，无阻塞。
  - `distiller` 的 `unresolved` 逻辑引用 `write_stdin` / `initialOutcome`（Codex PTY 专用）——Claude 永不产生这些名字，缺失即自然忽略，无害。
  - `httpAdapter` 的 `meta.capabilities?.handoff === false` 门卫对 Claude 生效；`adapterResolver(agentType).captureSession/generateHandoff` 已支持按 agent 路由（Pi 同款）。
- **结论：Shared Core 兼容，仅需新增 Claude extractor + wiring，无核心重构。**

**各字段可安全恢复：**
- **Goal**：取前台真实 `user` 消息（排除 tool_result / task-notification / compact summary）。确认。
- **Progress**：distiller 从 `Test execution`（is_error 判定）与 `File edit/write` operation 生成。确认。
- **Validation**：distiller 统计 test 命令 exit 0/非 0；Claude 仅有 is_error，无 exit_code 值，但足够判通过/失败。确认（粒度比 Codex 略粗）。
- **Pending / Follow-up**：distiller 的 terminal label 恢复，agent 无关。确认。

**缺失 / 歧义（如实报告）：**
1. **Bash 无结构化 exit_code**——只能二态（is_error 失败 / 否则成功），无法得到具体退出码。可接受（Claude 对失败命令确实置 is_error:true）。
2. **无结构化 truncation 标记**——长输出按原样，不判截断。
3. **parentUuid 分支不重建**——同文件内 abandoned rewrite 视为活跃；本机样本无该场景，已记录为限制。
4. **compact summary 需精确识别**——依赖 `compact_boundary` 前缀 + "This session is being continued..." 开头；若压缩未被标记（旧版本），可能把 summary 误当 Goal 候选 → 需加 content 前缀过滤。
5. **`toolUseResult` 可选且 type 多样**——仅作 filePath 旁证，不依赖其判 outcome。
