### Exact Self-Integration claim

Tier 1 Self-Integration is supported only for session sources expressible by the existing declarative reader catalogue. An Agent can follow the shipped Integration Skill, emit a data-only descriptor and evidence report, run the public verifier, inspect diagnostics, correct its declaration, and obtain an observed session verdict without adding Margin code. Installation remains a separate user-confirmed operation.

This is a bounded capability, not universal Agent support. Opaque/private storage continues to require native readers. SQLite, encrypted/binary stores, remote/API stores, and metadata split across non-transcript files are outside Tier 1. A descriptor must not substitute logs, fabricated sessions, or a trial-specific root for the real store.

The real positive trial is Claude Code CLI 2.1.258 on Windows, routed through an existing proxy with `gpt-5.6-luna` driving most of the revalidation. Claude already has a native Margin reader; the trial used the separate `claude_code` descriptor type and the generic transcript path. This proves the generic mechanics on a real store, not support for a wholly new Agent family, every platform, every Claude version, or every installed session.

The accepted whole-store declaration projected 4 of 14 real session files: five project directories supplied five matched files, one lacked the declared updated timestamp, and four projected with native id/cwd/timestamps. The current directory layout selects one transcript per directory; it does not enumerate every session inside a project group. A harness using explicit per-project roots projected 11/14, with three incomplete transcripts dropped. That diagnostic control is not a portable grouped-root solution and is not the Agent's autonomous result.
