# Margin 记忆路由与中文召回设计

## 目标

在不更换 Pi 运行时、不增加 UI 的前提下，以轻量混合检索修复已确认中文记忆无法召回的问题，并给终端试点增加可测试的最小写入门控。试点仍只覆盖“简历投递与投递记录维护”。

## 已确认问题

一条记忆记录已由用户确认至 v2，但新 Session 的 `/memory` 返回空。当前检索把连续中文文本当成完整 token，导致“继续简历投递”和“使用新版简历投递”没有完全相同的 token。

当前写入决策主要由模型自行选择四个工具。Core 会验证权限、项目、状态和版本，但缺少一个明确、可回归的路由规则来区分“不保存、状态更新、行动更新、候选长期记忆”。

## 范围

### 轻量混合召回

- 保留现有英文、数字和 Unicode 字词匹配。
- 为中文连续文本增加确定性的字符 n-gram（2–3 字）匹配，不引入外部分词服务或独立向量数据库。
- 增加可注入、默认关闭的 embedding 接口。启用时，SQLite 保存记忆向量及 embedding 模型版本，不引入独立向量数据库。
- 词法分数与语义相似度通过固定权重融合，再结合置信度和时效排序。具体权重进入版本化检索配置，不能由单次请求任意修改。
- embedding 未配置、超时、模型版本不匹配或调用失败时，必须明确降级到词法检索，不能让召回整体失败。
- 纯词法模式只有存在实际文本重叠时才能召回；语义模式可以召回无字面重叠但相似的内容，并标注召回原因。
- 继续执行项目隔离、确认状态、有效期、删除和 superseded 过滤。
- 新增真实短语回归：“继续简历投递”可以召回“后续使用新版简历投递”。
- 使用假的确定性 embedder 测试语义融合、模型版本隔离和降级，不在自动化测试中调用收费 API。

### 最小写入门控

新增纯函数路由器，将候选信息分类为：

1. `ignore`：寒暄、确认词、无持续任务价值的普通聊天；
2. `state`：当前阶段、当前步骤、阻塞和已发生进度；
3. `action`：明确的下一步、期限、待完成事项；
4. `memory_proposal`：跨 Session 仍稳定有用的偏好、约束、事实或上下文。

路由器只生成建议，不直接写数据库。Pi 仍通过现有四个工具执行实际写入，Core 继续负责最终授权和校验。一次输入可以同时产生 `state`、`action` 和 `memory_proposal`，但普通聊天不得自动升级为长期记忆。

候选长期记忆必须满足：内容具体、未来可复用、具有稳定意图，且不只是一次性进度。所有候选仍以 `proposed` 写入，必须经宿主确认后才可召回。敏感信息不因自动路由获得额外权限。

## 运行时集成

终端控制器在调用 Pi 前，把路由结果以隐藏、无权限的建议附加到上下文。建议只说明推荐目标和原因，不包含新的执行权限。模型必须以 Core 工具结果为准；宿主继续显示部分失败警告和审计编号。

## 测试与验收

- 中文召回单元测试覆盖相关、无关、跨项目、未确认和过期记忆。
- 混合检索测试覆盖词法命中、纯语义命中、融合排序、embedding 失败降级和模型版本不匹配。
- 路由器使用固定中文样例覆盖四类结果、模糊数量和普通聊天污染。
- 终端上下文测试确认路由建议存在，但工具白名单和权限不变。
- 使用现有真实数据库确认记忆后，执行 `/new` 与 `/memory`，必须显示该记忆及来源。
- 完整仓库测试必须通过。

## 不在本轮范围

- 独立向量数据库、知识图谱和线上批量向量迁移；
- 自动确认长期记忆；
- 正式手机或桌面前端；
- 招聘网站、邮箱或文件读写；
- Pi、DeepSeek Harness、Codex 的最终选型。

## 底座评估触发点

完成本设计并至少积累一轮真实投递记录后，启动 Pi Agent、DeepSeek Harness 和 Codex 开源项目的技术评估。评估使用同一数据库、同一任务输入和同一四工具权限边界，比较集成复杂度、工具协议稳定性、Session/压缩、可观测性、移动入口适配和维护风险，不使用不同模型输出质量替代架构比较。
