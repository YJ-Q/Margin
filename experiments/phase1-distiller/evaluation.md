这组核对说明：新的 Handoff 能提供 standard 缺少的、不重复操作所必需的事实；它没有证明新的 Agent 实际会正确采取行动。尤其当前样本只有 7 条标准化对话，主要是 Phase 0 实验开发，不包含独立的业务功能失败—修复—测试闭环。

## 真实性约束验证

定向测试覆盖混合结果、缺失/重复 ID、嵌套 JSON、并行有序输出、截断、动态代码、字符串中的伪工具调用、PTY 延后完成、错误进程 ID、测试命令识别、Assistant 与失败测试冲突、失败后的成功重试、文件缺失与报告时效、Workspace 内容变化/删除，以及真实 191 条记录回归。

测试不执行任何历史脚本，不连接模型，不重跑 Phase 0 的安装/发现/验证，不变更原始 Session。文件变更场景只在临时夹具中发生。当前源样本没有直接测试执行；对 test execution/result 和冲突判定的覆盖来自明确标注的合成夹具。

## Token 比较的口径

`output/measurements.json` 使用固定的 js-tiktoken 1.0.21 / o200k_base 编码，报告四种口径：原始 JSONL、Phase 0 Context JSON、去掉 bootstrap/私有 reasoning 等内容的可见对话与完整工具文本、最终 Handoff；并单列 standard 与纯对话长度。

不要把原始 JSONL 中大量工具输出、重复包装和私有内容带来的高压缩比例当作 Continuation Quality。Margin 允许比 standard 更长，以保留决定下一步行动的证据。长度没有硬上限，也没有按最后 N 条截取用户要求。

## 当前判断和唯一后续验证

核心假设获得**离线事实恢复层面的支持**，尚未获得真实 Agent 行为层面的证明。当前自动 Next Step 仍较保守，复杂技术决策原因和业务语义没有被自动重建。

唯一下一步：选择一个独立且包含“失败—修复—测试”过程的开发 checkpoint，固定接手问题，对比 standard 与 Margin Handoff 下的真实接手行为，检查是否重复修改、误判测试状态、或遗漏必须处理的下一步。固定事实正确性后，再根据实际续接表现调整语义提炼；本轮没有自动启动此实验。
